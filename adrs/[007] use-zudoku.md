# [007] Use Zudoku

## Status - ACTIVE

## Context

In order for MadChatter to be easy to pick up and get into, we want to cover three areas for
documentation:

1. General user docs. This meaning core concepts, what and how to manage resources, what the
   application can and cannot do. Also should have some setup guide.
2. API docs. Just outline of the API used. May be useful for any developers.
3. Dev docs. General architecture overview, links to ADRs, where/how to tweak things.

## Decided Approach

To use Zudoku to build our docs. Some reasons include:

1. Uses our UI component library shadcn.
2. Can handle both .mdx files and autogenerated OpenAPI docs from FastAPI.
3. Simple to auto build and deploy via cloudflare pages.

## Governance

- Docs are auto built and deployed as soon as there are any changes to our repo. OpenAPI docs can
  also be auto built and shown.
- For other things, such as installation, user guide etc, we will aim to write the docs closer to
  the end, such that the docs do not have to be changed frequenter. If any changes do occur, it is
  the job of whoever authored the changes to make sure the docs are up to date. Otherwise, whoever
  finds an issue with the docs should update them.
